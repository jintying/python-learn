## 一、先说三句话（这三句就是函数的全部）

### 第 1 句：函数 = 给一段代码起个名字

你在做路测，每天要算接管率。没有函数，就是每天把那 3 行代码复制一遍。
第 30 天公式要改，你得改 30 个地方，漏一个就错。

**函数就是：把那段代码起个名字，以后喊名字就行。**

### 第 2 句：定义 ≠ 执行（90% 的人卡在这）

```python
def 打招呼():          # 定义：把菜谱写进本子里。锅还是凉的
    print("你好")

打招呼()               # 调用：照着菜谱真的炒一盘
```

`def` 只是**登记**，不会执行里面的任何代码。
**加括号 `()` 才是"去做"。**

### 第 3 句：print 是喊出来，return 是交出来（卡住的真正根源）

```python
def 错误示范():
    print(3 / 100 * 1000)     # 喊出来了，屏幕上看得见

jieguo = 错误示范()
print(jieguo)                 # None ← 你根本拿不到！
```

```python
def 正确示范():
    return 3 / 100 * 1000     # 交出来了

jieguo = 正确示范()
print(jieguo)                 # 30.0 ← 拿到了
```

**print 是给人看的，return 是给程序用的。**

> 这就是为什么要把你的 `log_analyzer.py` 重构：你原来全程用 `print`，
> 所以它只能"跑给人看"，pytest 拿不到任何值，没法断言。

## 四、最重要的学习方式：动手改

每个文件最后都有一个 **【动手改】** 区块，那不是摆设。

光看代码是学不会的，就像看别人开车学不会开车。
你必须：

1. 打开文件（推荐用 VS Code）
2. 改一行
3. `Ctrl + S` 保存
4. 跑一遍（`run.bat` 然后输课程号）
5. 看输出变成什么样了

**最有效的一个动作：把代码故意改坏，看报错长什么样。**
报错的最后一行会告诉你是"什么错"，倒数第一个 `File` 行会告诉你是"第几行"。

## 五、卡住的时候（一定会卡，这很正常）

### 情况 1：报错了，看不懂

看报错的**最后一行**。那是"什么错"。
往上找**最后一个** `File "...", line 8` 那行，那是"第几行"。
去那一行，重点检查三件事：

- 名字打错了吗？（大小写、拼写）
- `if` / `for` / `def` 那一行末尾的冒号 `:` 漏了吗？
- 缩进对吗？（该空 4 个格的地方空了没）

`06_报错怎么看.py` 里有一整课讲这个。

### 情况 2：跑完屏幕上什么都没有

十有八九是**只写了 `def`，忘了调用**。
`def` 只是登记，不调用就什么都不会发生。

### 情况 3：外面接到的值是 `None`

十有八九是**函数里用了 `print`，没用 `return`**。
回到第 3 句话。

### 情况 4：感觉自己很笨，学不会

不是你笨。是函数这个东西，教学顺序普遍是反的 ——
教程一上来就讲 `def`、参数、返回值，但没告诉你"我为什么要写这玩意儿"。

所以这个文件夹里，`02_为什么需要函数.py` 是第一课之后最先看的。
**先有"被逼出来的痛"，再学语法，就通了。**

还有个事实：你之前的 `log_analyzer.py` 能跑起来，用了 `os.walk`、
`Counter`、命令行参数、异常处理 —— 这些都不是新手会的东西。
**你不是不会，你是"会写但没形成体系"。** 这次就是来补体系的。

## 六、学完之后去哪

跑完 07 和 08 之后，回到 `pytest-learn` 文件夹（就是上次那套 pytest 示例）。
你会发现那些代码突然能看懂了：

```python
def test_parse_version_normal(text, expected):
    assert parse_version(text) == expected
```

因为你现在知道：
- `def` 是定义一个功能
- `parse_version(text)` 是调用，`text` 是参数
- `return` 交出来的东西，才能被 `assert` 拿去做判断

**先函数，后 pytest。顺序不能反。**
这就是为什么我这次没有直接继续讲 pytest，而是先回来补基础。
